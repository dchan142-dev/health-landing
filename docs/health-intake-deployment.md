# 健康問卷：部署與日常使用

程式入口 `/intake/`；API `/api/health-intake/*`。這個分支包含問卷、個別帳號、伺服器儲存及管理頁。**上傳 GitHub 不等於已正式啟用**：先完成以下資料庫和 Vercel 設定，才能讓客人登入。

## 正式啟用

1. 在 health-decoder.com 原有 Vercel 專案的同一範圍建立受控 PostgreSQL 資料庫（例如 Neon），使用供應商要求 TLS 的連線字串。不要把資料庫放在公開靜態網站目錄。選定資料所在地、存取人員、保留期和備份政策。
2. 在 Vercel **Production** 環境設定 `.env.example` 中首四個變數：
   - `APP_ORIGIN`：`https://health-decoder.com`，無末尾斜線。帳號登入請固定使用這個網址，避免 www 和非 www 混用。
   - `DATABASE_URL`：私人 PostgreSQL 連線字串，包含供應商要求的 TLS 參數。
   - `BETTER_AUTH_SECRET`：至少32字元的獨立隨機秘密。
   - `DATA_ENCRYPTION_KEY`：32個隨機位元組，以 base64 表示。與登入秘密分開保管；備份時也要保管金鑰，否則無法還原答案。不要直接換金鑰，現有資料須先遷移。
3. 在可信任的本機或部署工作環境執行 `npm ci`。把上述變數放在本機未提交的 `.env`，再加入 `HD_ADMIN_NAME`、`HD_ADMIN_EMAIL`、`HD_ADMIN_PASSWORD`（最少12字元）。執行 `node --env-file=.env scripts/setup-db.mjs` 建立資料表及第一個管理員。程式不會列印密碼；第一個管理員已存在時不會再建立。後續只更新資料表時移除 `HD_ADMIN_*` 再執行。
4. 初始化後移除 `HD_ADMIN_*` 環境設定，安全保存管理員密碼。不要把 `.env`、客人紀錄或真實登入資料上傳 GitHub。
5. Vercel 專案使用 Node.js 22 或更新版本；採用本儲存庫 `vercel.json` 的 build/output 設定。先用**獨立測試資料庫**及該預覽部署的固定 `APP_ORIGIN` 測試分支。預覽與正式環境不要共用客人資料庫或金鑰。Vercel 若自動注入 Web Analytics/Speed Insights 腳本，請從問卷頁移除，以免與嚴格 CSP 衝突。
6. 確認測試後合併並部署。先用虛構客人走一次「建立帳號→登入→填寫→重載續填→登出／重登入→提交→管理員查看→重開」，完成後才派發正式客人帳號。

Vercel 正式部署的 `npm run build` 會在打包後執行資料表初始化；初始化失敗會中止新部署。首次可透過 Production 的 `HD_ADMIN_*` Secret 建立管理員，完成後清空這些一次性設定再部署。相同管理員已存在時保留原密碼，不會在重新部署時重設；不同管理員存在時拒絕新增。預覽及本機打包不執行正式資料庫初始化。

部署驗收如建立專用虛構帳號，可在受控正式 build 設定 `HD_VERIFICATION_CLEANUP_EMAILS` 為其電郵 JSON 陣列。清理只接受 `hd-deploy-check-<十六進位或連字號>@example.test` 命名空間、稱呼恰為「部署驗證專用」及一般客人角色；以交易刪除這些帳號、關聯問卷及稽核資料，不接受一般客人的電郵。清理後清空此設定。

秘密可用 Node.js 的 `crypto.randomBytes` 產生；登入秘密用至少32隨機位元組，答案金鑰必須正好32位元組，再轉 base64。只在私密管理環境執行及保存，不要貼到對話、issue 或 PR。

## 給跟進者

- 到 `https://health-decoder.com/intake/` 用管理員帳號登入，即見管理列表；無需另一個公開管理網址。
- 直接把問卷網址交給客人。客人按「自行註冊」，填稱呼、電郵及自己的密碼，確認資料使用同意後便可開始填寫；已有帳號可直接登入續填。
- 若客人需要協助，管理員仍可按「建立客人帳號」。一般客人不用由管理員建戶或分配密碼。
- 密碼最少12字元。註冊表會確認兩次輸入一致；新帳號固定為普通客人，不能自行取得管理員權限。每個來源最多5次／10分鐘註冊。註冊同意稽核版本為 `self_register_consent_v1`。
- 本版沒有電郵驗證或自動重設密碼寄信服務；不會顯示已寄信。重複電郵維持通用回覆，不會取代原有密碼或問卷。
- 客人每次停下前確認顯示「已儲存」。下次用同一帳號可在另一裝置續填。登入有效期約8小時，閒置太久可能要重新登入。
- 手機填寫採單欄介面，使用「跳到其他部分」下拉選單，底部有「儲存進度／下一部分」。表格改為逐筆卡片，先顯示一筆，可按「新增一筆」。
- 填到一半可按「儲存並離開」：先等待伺服器確認保存，再結束登入。看到「進度已儲存」才可關閉；日後登入會自動載入答案及上次的部分。斷線、逾時或回覆不完整時保留畫面並提示，不能顯示儲存成功。
- 登入頁支援手機電郵鍵盤、自動填入及顯示／隱藏密碼。「忘記密碼」會提供聯絡跟進者的安排；本版不會假稱已寄出重設電郵。
- 已儲存草稿會出現在管理頁。提交後鎖定，管理員按「重開讓客人修改」才可再填。
- 忘記密碼時先透過既有私密渠道確認身份，再重設。重設會撤銷客人其他裝置的登入。
- 本版沒有報告照片上傳，沒有自動診斷、評分或保健品推薦。報告可在文字欄填寫日期、數值、單位，照片沿用既有私密交付渠道。
- 「有填寫 X/22 題組」表示至少有一欄填寫，並非確認所有資料齊全。只要求稱呼及明確提交同意；其他項目可留空／不清楚。

## 保存與失敗處理

答案由伺服器保存至資料庫，使用 AES-256-GCM 加密；密碼由 Better Auth 雜湊，登入使用 HttpOnly cookie。系統不把健康答案存入 localStorage。這些措施仍需配合受控資料庫帳號、HTTPS、管理員保安及備份。

介面會顯示未儲存、正在儲存、已儲存或錯誤。遇到錯誤保留當前畫面，按「重試儲存」。登入過期可按「重新登入」使用**同一帳號**恢復。不要關掉仍有未儲存答案的分頁。離線關頁不能保證保留。

若另一分頁已更新，伺服器拒絕舊版本，不會自動覆寫。先「下載目前答案」私下保存，再重新載入及人工核對補填。同一瀏覽器切換帳號時，舊分頁的儲存與提交會因帳號不符被拒絕。未儲存而登出時，可選擇先下載，再捨棄未儲存內容並登出；只保留伺服器最後成功儲存版本。下載是個人健康資料檔案，並不代表已上傳；本版沒有匯入功能。瀏覽器的列印／另存 PDF 也會產生含健康資料的檔案。

## 查閱、更正、刪除及備份

由帳號提供者處理客人的查閱、更正、撤回或刪除要求，並在收集前交代實際聯絡方法及保留期。問卷中的文字不取代營運者的私隱政策；正式啟用前應在原站提供此政策及聯絡方式。既有首頁不會被本功能修改。

刪除本版需由資料庫管理員在受控環境處理，管理頁未設一按刪除。先核實身份與保存義務，按**明確使用者 ID**刪除 `"user"` 列；Better Auth 關聯及 `hd_record` 的外鍵會連帶刪除紀錄。再按同一 ID 清理 `hd_audit.actor_id`、以及相關記錄 ID 的稽核列。刪除前在測試資料庫驗證查詢及範圍；不要憑模糊姓名篩選。依備份政策處理備份中的副本，告知刪除時間表。

資料庫供應商開啟定期備份及還原演練；答案金鑰另行安全備份。稽核表記錄管理操作及提交動作，未記錄答案內容。不要把 API 請求 body、cookie、密碼或答案送到日誌或分析服務。部署所用的 Vercel 和資料庫服務均會參與資料處理，應按實際安排向客人說明。

## 本機驗證

```
npm ci
npm test
npm run build
```

`npm start` 啟動 localhost:3010 的開發版，使用 `.local-data/` 內 PGlite PostgreSQL 引擎，**只供虛構資料測試**。首次啟動時從私密環境提供 `HD_ADMIN_EMAIL` 及 `HD_ADMIN_PASSWORD` 建立測試管理員。本機開發模式的 cookie 和金鑰設定不供公開託管。正式環境使用 `api/health-intake.js`、受控 PostgreSQL 及獨立正式金鑰。

自動 API 測試使用真實 PGlite 引擎驗證登入、跨客戶隔離、跨站寫入、草稿重載、衝突、提交鎖定、管理員重開、重設密碼和答案加密。測試僅使用虛構資料；仍需完成上述正式環境驗收。
