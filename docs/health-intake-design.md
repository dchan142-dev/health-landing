# 客人健康問卷設計與實作計劃

日期：2026-11-11（香港）

目的：在 health-decoder.com 增加獨立 /intake/，讓客人以個人電郵和密碼登入，逐步完成既有22題問卷、保存草稿、下次繼續及正式提交。現有靜態首頁及專題頁保持可用。

選擇：沿用原有 HTML/CSS/JS，增加 Vercel Node API、Better Auth 和 PostgreSQL；不以 HTML 共用密碼或 localStorage 當正式登入與保存。獨立新網站會分散現有入口，因此本版採原站整合。

介面：原站深藍、青綠與白色，手機優先、大字、七個章節、可隨時返回、清楚顯示未儲存／正在儲存／已儲存／失敗，不假裝離線資料已同步。中性問題，不自動配產品、不作診斷，不把本次客人的個人病史放進共用表單。

權限：客人可自行註冊及設定密碼，只讀寫自己的紀錄；管理員可查看紀錄、協助建立客人帳號、重設密碼。公開註冊固定建立普通客人角色，拒絕權限欄位並限制註冊頻率。管理員角色在伺服器驗證，密碼交由 Better Auth 處理。Cookie session，API防跨站寫入，資料不存公用瀏覽器磁碟，登出清除畫面。

資料：22題所有核心內容、三天記錄、目前藥物及保健品、現有報告欄位。報告先以文字記錄及可提供清單收集，本版不提供附件上傳。草稿以版本條件保存，避免不同分頁互相覆蓋；提交後鎖定，由管理員重開才可修改。提供明確資料使用確認及列印紀錄；刪除要求由管理員依部署文件處理。

部署：沿用現有 Vercel 專案。啟用前須確認目標專案、資料庫、正式 URL 及管理員初始化；尚未連接資料庫時停止提供紀錄操作並清楚提示。

實作順序：
1. 以真正PostgreSQL引擎PGlite寫端到端API測試，先確認缺少功能時失敗。
2. Better Auth設定及資料庫schema、伺服器欄位驗證與權限。
3. 個人草稿、版本衝突、提交與管理員操作。
4. 共用問卷欄位、登入、填寫、回顧、管理畫面。
5. 完整測試、靜態資產打包、瀏覽器檢查及部署接線。

驗收重點：匿名及客人跨帳號不能讀取；密碼錯誤不能登入；頁面重載能取回；過期版本不能覆蓋；提交後不能偷偷改答案；跨站寫入拒絕；無資料庫時明確停用而非假成功；既有網站檔案保持一致。

手機使用要求：所有螢幕採單欄填寫、17px以上輸入文字、48px以上按鈕、直向卡片式記錄。章節以原生下拉選單切換；底部保留儲存及前後操作，支援手機安全區，輸入時避開鍵盤。登入頁支援電郵鍵盤、密碼自動填寫及顯示／隱藏密碼。

續填要求：「儲存並離開」必須在伺服器確認草稿後才登出，成功後顯示續填提示。失敗、逾時或非有效JSON回覆均保留當前答案，不可顯示儲存成功。重新登入載入已儲存答案及上次章節。忘記密碼沿用管理員核實身份後重設的流程，不宣稱已寄出尚未配置的郵件。
